# ComfyUI H3 Long Video

这是一个用于 MiniMax H3 长音视频生成的 ComfyUI 自定义节点插件。它把长音频识别并切成可审核的片段，使用唱歌或口播本地规则生成每段镜头简报；用户确认后，同一工作流按顺序逐段生成并自动合并成片，不需要另外运行分析脚本。

插件本身不接参考图、不识图，也不配置 AI 导演或大模型 API。参考图直接连接官方 MiniMax H3 节点；分段镜头简报可以直接连接下游文本输入，也可以通过提示词小助手和可选素材说明扩写为规范 H3 提示词。自动测试、真实 H3 试生成与人工验收范围记录在 `VERIFICATION.md`。

## 操作

1. 推荐打开“一体化”工作流上传歌曲，选择 singing 或 speaking。参考图直接连接官方 MiniMax H3 节点；长视频节点不接图、不识图，也不保存或转发图片。歌手模式可选择镜头活跃度和最远景别；表演强度按分段测量自动安排。语音识别默认使用当前 ComfyUI Python，并从 `ComfyUI/models/faster-whisper` 自动发现完整模型快照；技术设置里的两个路径只用于覆盖默认值。可接已有分离节点的人声；唱歌模式未接人声时，首次分析会从 PyTorch 官方地址自动下载约 319 MiB 的 HDEMUCS 权重，显示任务进度，完成后继续分析。
2. 一体化画布只显示一个 **音频分析与顺序生成** 节点。首次点击 ComfyUI 自带“运行”或单独运行该节点时，只执行音频识别、切分和本地运镜规划，完成后自动打开审核。试听每段和切点，按需编辑镜头简报，然后点击“保存并确认”。尚未确认时再次点击运行只会返回审核，不会提交 H3。
3. 示例工作流推荐把 `segment_brief` 连接提示词小助手的 `source_text`，其“用户提示词”是可选素材说明：需要精确指定图1、图2或人物与音频关系时再填写；留空时只扩写当前运镜和表演，不猜参考图内容。提示词小助手不是运行前置条件，也可以把 `segment_brief` 直接连接任何接受字符串的下游提示词输入；这种接法只输出精简中文镜头简报，不保证符合完整 H3 提示词格式。确认并关闭审核后，再点击 ComfyUI 自带的整张工作流“运行”，插件会接管同一工作流并从第1段开始顺序循环生成；此时若只运行 H3 长视频节点，仍视为重新分析并创建新项目。审核面板中的绿色“开始顺序生成”是整张工作流运行的快捷入口。
4. 控制器逐段提交，失败停止。“当前段完成后暂停”和“停止后续生成”都不会强制中断正在运行的 H3 片段。生成全部完成后自动裁掉模型补齐帧、合并视频、配回原曲；面板展示成片。

修改提示词只把该段标记为待重生成；移动一个切点会使切点两侧两段失效，同时撤销确认。其他完成段继续保留。首版移动切点但不增删段；需要改段数时调整分析参数。关闭浏览器不会终止已启动的服务器控制器；ComfyUI 重启后未知任务不会盲目重复提交。

完成后可在某一段点击“重新生成本段”。旧版本会保留到新版本成功；新版本失败时自动恢复原成功片段。可以“恢复上一版”并“仅重新合成”。规范化后的片段按输入视频、剪辑帧数和编码参数缓存，未修改片段不会再次运行 H3，也不会在每次合并时重复转码；最终 MP4 容器仍会重新创建并重新封装原曲。

普通继续使用该项目首次启动时保存的工作流快照，避免中途意外改变未完成段。点击“重新生成本段”时会明确使用当前画布快照，因此只应在有意让该段采用新参考图或采样设置时操作。

## 节点

- `H3LVUnified` / **H3 长视频 · 音频分析与顺序生成**：插件唯一公开节点。原生运行时分析音频；确认分段后由控制器让同一个节点按索引输出补齐音频、分镜、帧数和保存前缀。项目编号与当前索引是内部状态，不在画布中占用第二个节点。

审核面板的新项目只保存两项中文输入：“镜头方案”和“表演节奏”。开场构图、唯一运镜、结束构图和结束运动状态合并在同一条镜头方案中，生成时长由节点内部控制。简报不包含参考图、主体、服装、道具或配饰声明。旧的七字段项目仍可读取和生成；重新分析后使用精简格式。

运镜规划完全离线，不需要本插件配置大模型或 API Key。用户目录中的一个 JSON 文件分别保存 singing 和 speaking 规则；节点上的“运镜规则：查看与修改”会跟随当前 `mode`，只显示、保存或恢复当前模式的规则，另一套规则不会被覆盖。提示词小助手仍使用它自己的模型配置，两者互不读取。

唱歌模式每段只安排一种主要运镜，按低/中/高相对能量在轻微构图调整、小角度环绕、短距离横移和克制推拉之间选择。选择结果由音频内容和规则版本产生可复现种子，不使用所有歌曲相同的固定顺序；相邻片段不重复同一运镜类别，横移再次出现时优先换方向。口播模式始终使用正面中近景固定机位。人物中心和眼线使用统一构图锚点。参考图关系只存在于提示词小助手的用户素材说明与官方 H3 节点中。

## 安装

1. 关闭 ComfyUI。
2. 将仓库克隆或解压到 `ComfyUI/custom_nodes/ComfyUI-H3-LongVideo`。
3. 将 `examples/04_H3长视频_单节点一体化.json` 复制到自己的 ComfyUI 工作流目录并打开。
4. 安装示例工作流标出的外部节点：`comfyui-vrgamedevgirl`、`ComfyUI-Prompt-Assistant`、`ComfyUI-VideoHelperSuite` 和 `ComfyUI-KJNodes`。公开示例已移除只负责显示或分组的可选节点。
5. 准备相应 MiniMax H3 模型、VAE、CLIP 和 LoRA。模型不随本仓库分发，具体文件名可在工作流加载器中自行选择。
6. 通过 ComfyUI Manager 安装插件依赖，或在当前 ComfyUI Python 中执行 `pip install -r requirements.txt`。本插件额外声明的依赖只有 `faster-whisper`；首次识别会把 `large-v3-turbo` 下载到 `ComfyUI/models/faster-whisper`，已有完整快照会直接复用。
7. 确认 `ffmpeg` 与 `ffprobe` 位于 PATH，然后启动 ComfyUI。

本仓库不会升级 torch，也不下载 MiniMax H3 模型。ComfyUI 端复用现有 numpy、Pillow、torch、torchaudio、soundfile 和 aiohttp；不同整合包是否已包含这些基础库，需要在实际安装环境中确认。内置人声分离只在唱歌模式未连接 `vocals` 时按需下载官方 HDEMUCS 权重到 `ComfyUI/models/H3LongVideo/hdemucs_high_trained.pt`。下载使用 `.part` 临时文件，支持下次运行续传，并按固定大小与 SHA-256 校验后原子落盘；同一 ComfyUI 进程不会并发重复下载。

## 数据与隐私

- 最终成片只保存在本机 `ComfyUI/output/H3LongVideo/final_videos`，文件名为创建时间、模式和项目短编号。
- 可恢复项目保存在 `ComfyUI/output/H3LongVideo/projects/<project_id>`：`state` 是计划与诊断，`audio` 是原曲与人声，`takes` 是分段生成，`cache` 是可复用标准化片段，`work` 只保存当前合并的临时文件。
- 合并成功后删除对应的 `work/assembly_*` 临时目录；分段 take 与 cache 不自动删除，因为重新生成、恢复上一版和快速重新合成都依赖它们。
- 本插件的分段和运镜规划完全离线，不包含导演模型连接或 API Key 设置。
- 提示词小助手属于独立插件；其模型服务和凭据不由本插件读取、保存或发送。
- GitHub 仓库不包含模型、测试素材、输出、日志、缓存、API Key 或开发者机器路径。HDEMUCS 权重来自 `https://download.pytorch.org/torchaudio/models/hdemucs_high_trained.pt`，不由本仓库重新分发。

ComfyUI 端使用已有 numpy、Pillow、torch、torchaudio、soundfile、aiohttp 和 faster-whisper。合并使用 PATH 中的 FFmpeg/ffprobe。H3 模型只读引用，不复制；首次语音识别可能联网下载 Faster-Whisper 模型，唱歌模式未接外部分离人声时可能联网下载 HDEMUCS 模型。

## 目前限制

- 中文识别首版；唱歌错字、拖音和时间戳冲突会保留警告，需要检查。无文本不能作为无人声证明。
- 本地运镜方案是基于声学结构的可编辑草案，不声称理解歌词语义或完整曲式。规则通过也不能保证 H3 严格执行景别、运镜或人物连续性，必须检查真实生成结果。
- 唱歌模式的低能量片段可能采用“轻微呼吸式构图调整”，视觉上会接近固定机位；需要明显运镜时，应在审核面板修改该段镜头方案，或调整 singing 规则后重新分析。
- V1 只支持单歌手。双人演唱需要逐段/逐句的演唱者标注与额外身份、口型验收，当前不以全局下拉框伪装支持。
- 人物图自带的背景可能与场景图竞争；即使连线和提示词正确，生成仍可能回到人物图背景。需要检查每段最后一个实际保留帧，不能只看开头。夜间对照试验另存了人物/舞台统一参考工作流，不自动替换用户原图。
- 上半身参考不能唯一决定下装；拉远可能暴露模型自行补全的服装。真实运镜幅度也可能大于提示词要求，歌词段之间采用剪辑切换而非保证无缝长镜头。
- 每段预算先限制在 5–15 秒，短尾段可补齐生成后剪掉；这是首版策略，不是宣称 H3 的硬限制。
- 顺序生成只要求一个 `H3LVUnified` 和一个 VHS Video Combine 输出。PromptExpand 提示词小助手是推荐的可选格式器；旧双节点工作流仍会显示缺失节点，需要改用仓库示例工作流。
- 最终 MP4 使用原曲作为音源并编码为 AAC；保存的 source.wav 不被改动，不能声称 MP4 音频与 WAV 字节相同。
- 跨机器首次启动、依赖缺失提示和不同显卡上的 H3 执行效果仍需以实机结果为准。
- 当前仓库未附开源许可证；代码公开可见不等于自动授权再分发或商用。
