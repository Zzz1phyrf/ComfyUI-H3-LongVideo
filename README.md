# ComfyUI H3 Long Video（公开测试版）

这是 ComfyUI 自定义节点插件，不需要用户运行外部分析脚本。目前是开发预览版；自动测试、真实 H3 试生成与人工审美验收分别记录在 `VERIFICATION.md`，不将局部测试等同于发行验收。

## 操作

1. 推荐打开“一体化”工作流上传歌曲，选择 singing 或 speaking。图片模式只保留单歌手的两种明确方案：单图（人物与场景在同一张图）或双图（图1人物、图2独立场景）。歌手模式可选择镜头活跃度和最远景别；表演强度按分段测量自动安排。插件直接使用当前 ComfyUI Python 中的 Faster-Whisper，并在首次分析时把默认识别模型缓存到 `ComfyUI/models/faster-whisper`；节点不保存 Python 或模型绝对路径。可接已有分离节点的人声；未接时只尝试已缓存的 HDEMUCS 模型，不自动下载人声分离模型。
2. 一体化画布只显示一个 **音频分析与顺序生成** 节点。ComfyUI 自带“运行”让该节点进入分析阶段；完成后自动打开审核。试听每段和切点，编辑结束时间及自动分镜要求，点击“保存并确认”。未分析或未确认的生成工作流会在提交 H3 前被拦截。
3. 点击审核面板中的绿色“开始顺序生成”。每段自动送入原有 PromptExpand 扩写节点，再进入 H3；ComfyUI 自带“运行”只用于明确的当前段测试，不代替完整循环。
4. 控制器逐段提交，失败停止。“当前段完成后暂停”和“停止后续生成”都不会强制中断正在运行的 H3 片段。生成全部完成后自动裁掉模型补齐帧、合并视频、配回原曲；面板展示成片。

修改提示词只把该段标记为待重生成；移动一个切点会使切点两侧两段失效，同时撤销确认。其他完成段继续保留。首版移动切点但不增删段；需要改段数时调整分析参数。关闭浏览器不会终止已启动的服务器控制器；ComfyUI 重启后未知任务不会盲目重复提交。

完成后可在某一段点击“重新生成本段”。旧版本会保留到新版本成功；新版本失败时自动恢复原成功片段。可以“恢复上一版”并“仅重新合成”。规范化后的片段按输入视频、剪辑帧数和编码参数缓存，未修改片段不会再次运行 H3，也不会在每次合并时重复转码；最终 MP4 容器仍会重新创建并重新封装原曲。

普通继续使用该项目首次启动时保存的工作流快照，避免中途意外改变未完成段。点击“重新生成本段”时会明确使用当前画布快照，因此只应在有意让该段采用新参考图或采样设置时操作。

## 节点

- `H3LVUnified` / **H3 长视频 · 音频分析与顺序生成**：插件唯一公开节点。原生运行时分析音频；确认分段后由控制器让同一个节点按索引输出补齐音频、分镜、帧数和保存前缀。项目编号与当前索引是内部状态，不在画布中占用第二个节点。

“提示词”是插件生成、可编辑的 `H3LV_SEGMENT_V1` 中文镜头合同，不是最终 H3 提示词。它分别记录参考角色、开场构图、段内运镜、结束构图、入口剪辑、出口运动状态、表演、手持道具和穿戴配饰。人物、场景和音频角色由项目级参考清单固定。PromptExpand 按插件随附规则逐字段改写成六部分英文 Ref2VA 提示词，不负责重新导演；缺字段或固定镜头/运动状态矛盾会被拒绝。

默认“规则导演”完全离线。节点显示“导演模型 API Key：未配置/已配置”；选择“AI导演”前填写 OpenAI 兼容服务地址、模型名和 API Key，并连接当前图片模式实际使用的一张或两张参考图。插件一次发送参考图和结构化分段信息；识别短语只用于定位演唱短语，不用于推断剧情、服装或道具。不会上传原曲或分离人声。AI只返回景别、角度和运镜镜头表，不需要理解 H3；H3 特定组合限制由插件校验。API Key 保存到当前 ComfyUI 用户目录 `H3LongVideo/settings.json`，不进入工作流、项目清单或日志。

节点上的“导演规则：查看与修改”打开当前用户规则。AI 创作规则和规则导演 JSON 保存在 `ComfyUI/user/<当前用户>/H3LongVideo/rules`，不进入工作流；插件更新不会覆盖用户文件。AI 文本决定大模型如何规划镜头，JSON 同时约束规则导演、AI 导演和本地校验。JSON 格式无效或内容冲突时会明确报错，不会静默回退。

默认歌手规则的每一段都使用中近景真实横移，人物尺度保持稳定，不再安排固定机位或中景前推。连续片段可保持同一移动方向，再按节奏换向。`auto` 按分段能量自动调整速度，`moderate` 保持轻缓运镜，`dynamic` 使用更活跃但受控的运镜；强度只改变幅度和节奏，不改变参考人物和构图锚点。人物、环境和演唱身份按图片模式生成稳定的 `<Subject N>` / `<Picture N>` 映射。旧项目中的不兼容镜头会按当前规则迁移；要采用完整新规则仍建议重新分析。口播默认使用全程固定机位。

## GitHub 测试安装

1. 关闭 ComfyUI。
2. 在 `ComfyUI/custom_nodes` 中运行 `git clone https://github.com/Zzz1phyrf/ComfyUI-H3-LongVideo.git`，或下载仓库 ZIP 并解压为 `ComfyUI-H3-LongVideo`。
3. 使用 ComfyUI Manager 安装时，Manager 会按 `requirements.txt` 把固定版本的 Faster-Whisper 安装到当前 ComfyUI Python。手动克隆或解压时，使用当前 ComfyUI Python 执行 `python -m pip install -r requirements.txt`。
4. 将 `examples/04_H3长视频_单节点一体化.json` 复制到自己的 ComfyUI 工作流目录并打开。
5. 安装示例工作流标出的外部节点：`comfyui-vrgamedevgirl`、`ComfyUI-Prompt-Assistant`、`ComfyUI-VideoHelperSuite` 和 `ComfyUI-KJNodes`。示例候选已移除只负责显示/分组的可选节点。
6. 准备工作流本身使用的 MiniMax H3 模型、VAE、CLIP 和 LoRA；这些是示例工作流资源，不是长视频插件安装内容。
7. 确认 `ffmpeg` 与 `ffprobe` 位于 PATH，然后启动 ComfyUI。首次分析会联网下载 `large-v3-turbo` 到 `ComfyUI/models/faster-whisper`，后续复用本地缓存。

插件不会创建第二套 Python 环境，也不会强制重装 torch、numpy 或已有 CTranslate2。识别在同一个 ComfyUI Python 启动的短生命周期子进程中运行，完成后进程退出并释放识别模型；CUDA 识别不可用时自动尝试 CPU。首次模型下载失败会保留详细日志并提示检查网络和磁盘空间。

节点上的“导演模型 API Key”只配置本插件的 AI 导演。PromptExpand 属于独立插件，负责把中文镜头合同扩写为 H3 Ref2VA 提示词，仍需在 Prompt Assistant 中单独选择并配置可用的大模型服务；两套配置互不读取，也不会把 Key 写进示例工作流。

## 数据与隐私

- 最终成片只保存在本机 `ComfyUI/output/H3LongVideo/final_videos`，文件名为创建时间、模式和项目短编号。
- 可恢复项目保存在 `ComfyUI/output/H3LongVideo/projects/<project_id>`：`state` 是计划与诊断，`audio` 是原曲与人声，`takes` 是分段生成，`cache` 是可复用标准化片段，`work` 只保存当前合并的临时文件。
- 合并成功后删除对应的 `work/assembly_*` 临时目录；分段 take 与 cache 不自动删除，因为重新生成、恢复上一版和快速重新合成都依赖它们。
- 规则导演完全离线。
- AI导演只在用户主动选择后调用其配置的 OpenAI 兼容服务，并发送参考图和结构化分段信息；不发送音频。
- 导演模型 API Key 存在当前 ComfyUI 用户目录的 `H3LongVideo/settings.json`，不进入工作流和项目文件。
- 用户导演规则存在当前 ComfyUI 用户目录的 `H3LongVideo/rules`；每个新项目保存当次规则快照，后续修改不会暗中改变已经分析的项目。
- GitHub 公开测试仓库不包含模型、测试素材、输出、日志、缓存、API Key 或开发者机器路径。

ComfyUI 端使用已有 numpy、Pillow、torch、torchaudio、soundfile、aiohttp，并由 `requirements.txt` 增加 Faster-Whisper。合并使用 PATH 中的 FFmpeg/ffprobe。规则模式除首次下载识别模型外不需要网络；AI导演只调用用户明确配置的服务，不自动申请账号或安装服务商 SDK。

## 目前限制

- 中文识别首版；唱歌错字、拖音和时间戳冲突会保留警告，需要检查。无文本不能作为无人声证明。
- 规则导演是基于声学结构的可编辑草案，不声称理解完整曲式。AI导演返回的镜头表若不满足本地剪辑规则会明确报错，不会静默改成规则导演，也不会自动重复调用 API；不同服务和模型的格式、轴线与运镜约束遵循度需要实测。即使镜头表通过，仍不能保证 H3 严格执行景别、运镜或人物连续性。
- V1 只支持单歌手。双人演唱需要逐段/逐句的演唱者标注与额外身份、口型验收，当前不以全局下拉框伪装支持。
- 人物图自带的背景可能与场景图竞争；即使连线和提示词正确，生成仍可能回到人物图背景。需要检查每段最后一个实际保留帧，不能只看开头。夜间对照试验另存了人物/舞台统一参考工作流，不自动替换用户原图。
- 上半身参考不能唯一决定下装；拉远可能暴露模型自行补全的服装。真实运镜幅度也可能大于提示词要求，歌词段之间采用剪辑切换而非保证无缝长镜头。
- 每段预算先限制在 5–15 秒，短尾段可补齐生成后剪掉；这是首版策略，不是宣称 H3 的硬限制。
- 顺序生成只支持一个 `H3LVUnified` 一体化节点及一个 VHS Video Combine 输出。旧双节点工作流会显示缺失节点，需要改用仓库示例工作流。
- 最终 MP4 使用原曲作为音源并编码为 AAC；保存的 source.wav 不被改动，不能声称 MP4 音频与 WAV 字节相同。
- 当前为公开测试版；跨机器首次启动、依赖缺失提示和不同显卡效果仍需实机反馈。
- 仓库许可证尚需仓库所有者在公开发布前选择；代码可见不自动等于获得开源再分发许可。

## 测试

测试区分节点/路由/状态机、真实音频分析、合成测试视频合并和真实 H3 渲染。前几类通过不代替最后一类。
